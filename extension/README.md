# 包监控 (Chrome 扩展 MV3)

> 与本地 Node 网关 (`http://localhost:8910`) 实时联动的浏览器抓包与请求修改助手。

---

## 极简 3 步安装使用教程

### 第一步：打开 Chrome 扩展管理页
在 Google Chrome 浏览器地址栏中输入并回车：
```text
chrome://extensions/
```

### 第二步：开启开发者模式并加载已解压的扩展
1. 打开页面右上角的 **【开发者模式】(Developer mode)** 开关。
2. 点击左上角的 **【加载已解压的扩展程序】(Load unpacked)** 按钮。
3. 在弹出的文件选择器中，选择本目录：
   ```text
   /Users/huyaohang/plugins/hello/extension
   ```

### 第三步：点击扩展图标开始抓包与篡改
1. 在浏览器右上角扩展栏点击 **包监控** 图标。
2. 确认状态显示 **● 已连接包监控服务**。
3. 浏览任意网页，所有网络请求将自动捕获并毫秒级推送到看板；
4. 点击弹出层上的 **【打开包监控看板】** 按钮即可实时查看流量详情与动态 Mock / 篡改规则！

---

## 核心架构特性
- **MV3 原生标准**：基于 Chrome 最新 Manifest V3 规范，采用 `content_scripts` 的 `world: "MAIN"` 毫秒级注入。
- **双协议深度劫持**：无感包装 `window.fetch` 与 `window.XMLHttpRequest`，兼顾新旧各类前端请求库（Axios、Fetch、jQuery 等）。
- **动态 Mock 与请求篡改**：自动拉取网关规则，支持实时短路返回 Mock 数据、自动注入 Request Header、篡改 Request Body。
- **智能防死循环**：底层严格过滤对本地网关 `http://localhost:8910/__api/*` 的自身通信，杜绝递归死循环。

## v1.1 发送前劫持（断点）

以前的「劫持」其实是：预先写正则，发送时静默改 Header / Mock，请求已经飞走了才出现在看板。

现在可以像 Charles 一样：

1. 先照常抓包（劫持发送保持 **关闭**）
2. 点中目标请求 → **下次拦住这条**
3. 业务页再发一次，看板弹出编辑器
4. **按编辑发送 / 原样放行 / Mock 返回 / 丢弃**

也可以在顶栏把「劫持发送」设为 **匹配 / 全部 / 只拦一次**。超时默认 30 秒自动放行，避免页面卡死。

其它新增：流量搜索、重放、复制 curl、从请求生成 Mock 规则、可选拦响应、改写请求 Body 规则。

## v1.3 XHR 响应前断点

勾选看板顶栏的「同时拦响应」后，XHR 和 Fetch 都会在业务页收到终态事件前暂停。修改 Response Body、状态码或响应头，再点「修改后发送」，业务页的 `responseText` / `response` 以及 `load`、`loadend` 事件会使用改写后的内容。

## v1.4 已完成记录直接回写页面

日常改字段不用再走「下次拦住这条 + 同时拦响应」。在已完成的请求里改好 Response Body，点 **修改后发送**：

1. 请求已经出现在看板
2. 改某个字段
3. 点「修改后发送」
4. 原业务页自动刷新，并用这份数据重新渲染

「重放原请求」仍然只让网关再发一次，不碰原页面。

## v1.2 Postman 风格请求

看板现在提供两个顶层 Tab：

1. **抓包**：保留原有实时流量、报文审查、断点、规则、Mock、重放和 curl。
2. **请求**：选择 method，填写完整的 `http(s)` URL、Headers 和 Body，点击 **发送** 查看响应；也可以把当前抓包载入编辑器。

“请求”Tab 由 8910 网关直发，不经过浏览器扩展；发送结果会回流到“抓包”列表。Cookie、Authorization 等 Header 需要用户自行确认后再填写。
