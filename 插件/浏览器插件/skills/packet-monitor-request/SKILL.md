# 请求工作台

“请求”页是包监控看板中的 Postman 风格编辑器，支持 method、完整 URL、Headers、Body 和响应查看。

## 工具选择

- 优先使用看板顶层“请求”Tab，点击“发送”后由 8910 网关直发。
- 需要在 Codex 中执行时使用 MCP `send_request`；参数与 `replay_request` 相近，但语义是手工编辑后直发，不要求已有抓包记录。
- 发送结果会写入网关内存记录，并通过 SSE 回流到“抓包”Tab；可用 `get_request_detail` 继续查看完整响应。

## 操作边界

1. 发送前确认用户给出的目标 URL、方法以及是否需要携带 Cookie、Authorization 等敏感 Header。
2. URL 必须是完整的 `http://` 或 `https://` 地址。抓包里的相对路径会按页面 origin 自动补全；补全失败时才需要手工填域名。
3. 这是网关直发，不经过浏览器扩展，也不代表目标页面执行了请求；不要把它当成真实站点抓包证据。
4. `send_request` 属于写操作。没有用户明确发送、验证或重放意图时，只读取抓包记录，不主动发请求。
5. 发送失败时保留网关返回的原始错误，并区分 URL 校验失败、上游响应错误和网关不可用。
